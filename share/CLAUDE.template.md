## 自動チェック（Claude Code の hooks）
`.claude/settings.json` の hooks で、次を自動で行う。同じ指摘を 2 回したら、ここに足す。
- ファイルを編集した後（PostToolUse）: lint と型チェックを実行し、エラーがあれば差し戻す
- 新しいモジュールを作ったとき（PostToolUse）: 対応するテストが無ければ警告する
- 作業を終えるとき（Stop）: テストを実行し、失敗していれば差し戻す。ただし、実装のディレクトリ（`<src/>`）に未コミットの変更が無いときは、テストだけを書いた Red の段階とみなして差し戻さない
- Stop の hook は、`stop_hook_active` が true のときは何もしない（差し戻しの無限ループを避ける）

## ファイル操作
- git 管理下のファイルを移動・名前変更するときは `git mv` を使う（`cp` + `rm` にしない。履歴が途切れるため）。
- コミットするファイルは `git add <パス>` で明示する。`git add -A` / `git add .` は使わない（未追跡の無関係なファイルや秘密情報を巻き込むため）。
- コミット前に `git status --short` で `??`（未追跡）を確認する。中身の分からないファイルを表示しない。

## 進め方（SDD / TDD）
- `SPEC.md` と `specs/` が唯一の正。仕様に書かれていない挙動を実装しない。
- 機能ごとの詳細仕様は `specs/NNN-<name>.md`（またはディレクトリ `specs/NNN-<name>/`）に置き、連番は既存のものと連続させる。
- 作業は **仕様 → テスト → 実装** の順。仕様にない変更が必要になったら、実装を止めて修正案を示し、承認を得る。
- 機能に着手する前に、受け入れ基準（Given / When / Then、ID 付き）を書いて承認を得る。
- Red → Green → Refactor を守る。テストより先に実装を書かない。
- テストが失敗しても、テストを書き換えて通さない。テストが仕様と食い違うときだけ、仕様を確認して直す。
- 外部とのやり取り（API、メール、DB、ネットワーク）は、テストではモックかフェイクにする。
- コミットは、1 つの機能（または変更）の実装が終わり、テストがすべて通った段階で、テストと実装をまとめて 1 つの `feat:`（不具合の修正は `fix:`）にする。Red の段階ではコミットしない。
- Refactor をしたときは、テストが通ったまま `refactor:` として別にコミットしてよい。仕様の追加・変更は、承認を得た段階で `docs:` としてコミットする。
- pre-commit はすべてのコミットで通す（`--no-verify` で飛ばさない）。
- カバレッジの目標は <80〜90>%。
- 各ステップで、いまの段階（Red / Green / Refactor）を短く報告する。

## 仕様の値の扱い
- 仕様の数値・しきい値・上限には、**[決定] / [暫定] / [未決]** のいずれかが付いている。
- **[暫定]** の値は変更してよいが、変えたら理由を報告する。確定は実測のあとに人が行う。
- **[未決]** の項目は、決まるまで実装しない。必要なら、仮実装であることを明記して質問する。

## 秘密情報
- API キーや認証情報は `.env` のみに置く。コード・ログ・コミット・チャットに含めない。
- `.env.example` を用意し、実際の値は入れない。
- `.gitignore` に `.env`、`.env.*`（`!.env.example` で見本だけ除外）、エディタの一時ファイル（`*.sw[a-p]`、`*~` など）を入れる。
- pre-commit で、API キーらしい文字列を含むコミットを止める。見つけたときは、ファイル名だけを表示する（値を表示しない）。
- `.claude/settings.json` の `permissions.deny` で、Claude Code が `.env` を読む・編集する操作を禁止する。設定の確認が必要なときは、値を出さずに「設定されているか」だけを確かめる。
- 秘密情報が漏れたら、すぐに失効させて作り直す。そのあとで履歴から消す（失効が先）。
