# 011: ダイジェストの HTML の生成

- 状態: 実装済み
- 関連: SPEC.md §8（配信：件名、構成、各記事の表示、フッター、静的 HTML の出力）、§6（失敗した記事は原題と原文リンク）、§5（取得に失敗したソースをフッターに表示）、007（費用の累計）、009（セクション）、010（要約）

## 目的
要約（010）の結果から、メールの件名・HTML の本文・テキストの本文を作る。同じ HTML を静的なファイルとしても出力する。

## 範囲
- 含む:
  - 件名の生成
  - jinja2 のテンプレートによる HTML とテキストの本文の生成
  - フッター（取得に失敗したソース、LLM の費用）と、お知らせ（LLM を使えなかった等）の表示
  - `output/YYYY-MM-DD.html` への書き出し
  - 設定値の追加
- 含まない:
  - メールの送信：012
  - `digests` テーブルへの記録、お知らせの文言を決めること：013（この機能は渡された文をそのまま表示する）

## 入出力
- 入力: 要約の結果（010 の `SummarizedArticle` のリスト。009 のセクションの順）、配信日（日本時間の日付）、ソースごとの取得結果（004 の `SourceHealth` のリスト）、費用の累計（007 の `Spent`）、為替レート、お知らせ（文字列のリスト。無ければ空）
- 出力: `RenderedDigest`（`subject`、`html`、`text`）

### 追加する設定値
| 変数 | 型 | 既定値 | 用途 |
|---|---|---|---|
| `TEMPLATES_DIR` | パス | `templates` | テンプレートの置き場所（CLAUDE.md のディレクトリ構成） |
| `OUTPUT_DIR` | パス | `output` | 静的 HTML の出力先 |

## 振る舞い

### 件名
`[AI Digest] YYYY-MM-DD 注目 N 件`（日付は配信日、N は記事の件数）。SPEC §8 のとおり。

### 本文の構成
1. お知らせ（あれば、本文の先頭に箇条書き）
2. セクション（009 の順）。記事の無いセクションは出さない。見出しは次のとおり。
   | セクション | 見出し |
   |---|---|
   | `claude_code` | 今日の最重要（Claude Code 手法） |
   | `claude_code_update` | Claude Code 更新情報 |
   | `llm` | LLM 動向 |
   | `other` | その他 |
3. フッター

### 各記事
- 要約できた記事：
  - タイトル：`title_ja`（原文へのリンク）
  - 要約：`summary`（2〜3 文）
  - AI活用：`apply_to_claude_code`（空でなければ。見出しは「AI活用」。決定事項 1）
  - ソース名（`source_id`）と、原文のリンク
- 要約できなかった記事：原題（原文へのリンク）、ソース名、「要約なし」の表示

### フッター
- 取得に失敗したソース：`status = error` のソースの `source_id` とエラーの内容（先頭 200 文字）。無ければ「すべてのソースから取得できました」。
- LLM の費用：`本日 X.XX 円（$0.0000）／ 今月 Y.YY 円（$0.0000）`。円は為替レートで換算し、小数 2 桁。ドルは小数 4 桁。

### 記事が 0 件のとき
件名は `注目 0 件`、本文には「本日の注目記事はありません」とフッターを出す（送るかどうかは 013 が決める）。

### HTML とテキスト
- HTML はメールで崩れにくいよう、CSS をインラインで書いた単純な構造にする（外部の CSS・画像・スクリプトは使わない）。
- jinja2 の自動エスケープを有効にし、記事のタイトル・要約・エラーの内容など外部から来た文字列はすべてエスケープする。
- テキストの本文は、同じ内容をプレーンテキストにしたもの（メールの代替パートとして 012 で使う。決定事項 2）。

### 静的 HTML
- `OUTPUT_DIR/YYYY-MM-DD.html` に HTML の本文を UTF-8 で書き出す。ディレクトリが無ければ作る。同じ日のファイルがあれば上書きする。

## エラー時の挙動
| 状況 | 動作 |
|---|---|
| テンプレートが無い・構文が不正 | 例外をそのまま呼び出し側に渡す（013 が失敗として扱う） |
| 出力先に書けない | 例外をそのまま呼び出し側に渡す |

## 受け入れ基準
- **AC-011-1**: Given 設定値を設定していない / When `Settings` を作る / Then `templates_dir` は `templates`、`output_dir` は `output` になる。`.env.example` に載っている（AC-001-13 のテストで確認する）
- **AC-011-2**: Given 配信日 2026-10-17 と記事 7 件 / When 生成する / Then 件名は `[AI Digest] 2026-10-17 注目 7 件`
- **AC-011-3**: Given `claude_code`・`llm`・`other` の記事があり、`claude_code_update` の記事が無い / When 生成する / Then HTML とテキストに、3 つのセクションの見出しがこの順で出て、「Claude Code 更新情報」の見出しは出ない。各セクションの中の記事は入力の順
- **AC-011-4**: Given 要約できた記事 / When 生成する / Then `title_ja`（原文の URL へのリンク）、`summary`、「AI活用」の見出しと `apply_to_claude_code`、ソース名が出る。`apply_to_claude_code` が空なら、「AI活用」の欄は出ない
- **AC-011-5**: Given 要約できなかった記事 / When 生成する / Then 原題（原文の URL へのリンク）、ソース名、「要約なし」が出る
- **AC-011-6**: Given `<script>alert(1)</script>` を含む原題・要約・エラーの内容 / When HTML を生成する / Then エスケープされ、`<script>` タグとしては出力されない
- **AC-011-7**: Given 取得に失敗したソース 1 つと成功したソース 2 つ / When 生成する / Then フッターには失敗したソースの `source_id` とエラーの内容（200 文字以内）だけが出る。失敗が無ければ「すべてのソースから取得できました」が出る
- **AC-011-8**: Given 本日 $0.0025、今月 $0.0771、為替レート 160 / When 生成する / Then フッターに `本日 0.40 円（$0.0025）／ 今月 12.34 円（$0.0771）` が出る
- **AC-011-9**: Given お知らせ「LLM を使わずに作成しました」 / When 生成する / Then 本文の先頭にそのお知らせが出る。お知らせが無ければ、お知らせの欄は出ない
- **AC-011-10**: Given 記事が 0 件 / When 生成する / Then 件名は `注目 0 件`、本文に「本日の注目記事はありません」とフッターが出る
- **AC-011-11**: Given 記事のある入力 / When テキストの本文を生成する / Then HTML のタグを含まず、各記事のタイトルと原文の URL、フッターが含まれる
- **AC-011-12**: Given 生成した HTML と配信日 2026-10-17 / When 静的 HTML を書き出す / Then `OUTPUT_DIR/2026-10-17.html` に同じ内容が書かれる。ディレクトリが無ければ作られ、既存のファイルは上書きされる

## 実装方針（参考）
- 依存の追加：`jinja2`
- モジュール：`src/aidigest/render.py`、テンプレート：`templates/digest.html.j2`、`templates/digest.txt.j2`
- テストは、リポジトリのテンプレートをそのまま使う（テンプレートの誤りもテストで見つかる）

## 決定事項
1. **「AI活用」として `apply_to_claude_code` も表示する**：SPEC §8 の各記事の表示（タイトル・要約・リンク・ソース名）には無いが、要約のスキーマ（§6）で作っており、このアプリの目的（§1：Claude Code の開発に活かす）に最も直結するため。SPEC §8 の記述も合わせて直す。
2. **テキストの本文も作る**：HTML だけのメールは、迷惑メールと判定されやすく、テキストしか表示しないメールソフトでは読めないため、012 で HTML とテキストの両方を持つメール（multipart/alternative）にする。
3. **ソース名は `source_id` をそのまま表示する**：`sources.yaml` に表示名の項目が無いため。読みにくければ、Phase 2 で表示名の項目を足す。
4. **テンプレートはリポジトリ直下の `templates/` に置く**：CLAUDE.md のディレクトリ構成のとおり。パスは設定で変えられる。
