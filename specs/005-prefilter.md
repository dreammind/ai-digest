# 005: 事前の絞り込み（時間窓・除外キーワード・ソース別ルール）

- 状態: 実装済み
- 関連: SPEC.md §4 の 3（事前絞込）、§5（ソース別ルール、`qiita_search` / `zenn_topic` の時間窓の例外）、§7（`articles.status`）、001、003、004

## 目的
既読判定（003）を通った記事から、LLM を使わずに、明らかに対象外の記事を外す。
外した記事は `articles.status` を `skipped` にし、後の段階（006 以降）に渡さない。

## 範囲
- 含む:
  - 時間窓（`TIME_WINDOW_HOURS`、既定 36 時間）による絞り込み
  - 全ソース共通の除外キーワード
  - ソース別ルール（`require_keywords`、`hide_keywords`）
  - キーワードの照合方法
  - 外した記事の `status` を `skipped` にすること
  - 全ソース共通の除外キーワードを `sources.yaml` に置くための、001 の変更
- 含まない:
  - `highlight_keywords`（加点）とテーマ別キーワードによる採点：006
  - タイトルの類似度による重複話題の除去：006
  - コミットするかどうか：013（この機能はコミットしない）

## 入出力
- 入力: 003 が返した記事のリスト（`NewArticle`）、ソース設定（`id` → ソース）、全ソース共通の除外キーワード、現在日時、`TIME_WINDOW_HOURS`
- 出力: 絞り込みを通った記事のリスト（入力の順を保つ）

### 全ソース共通の除外キーワード（001 の変更）
`sources.yaml` のトップレベルに `exclude_keywords` を置けるようにする。

```yaml
exclude_keywords: ["求人", "hiring"]
sources:
  - ...
```

- 空でない文字列のリスト。省略したら空のリスト。
- 値が不正（リストでない、空の文字列を含む）なら `ConfigError` を送出する（ソースのエントリと違い、1 件だけ除外して続ける対象が無いため）。
- 001 の `LoadedSources` に `exclude_keywords` を加える。

## 振る舞い
入力の記事を 1 件ずつ、次の順に判定する。最初に当てはまった理由で外し、残りの判定はしない。

1. **時間窓**：`published_at` が `現在 − TIME_WINDOW_HOURS` より前なら外す。
   - `qiita_search` と `zenn_topic` のソースの記事は判定しない（取得時に `lookback_days` で絞っているため。SPEC §5）
   - `published_at` が無い記事は判定しない（通す）
2. **全ソース共通の除外キーワード**：いずれかを含めば外す。
3. **`hide_keywords`**（その記事のソースのもの）：いずれかを含めば外す。
4. **`require_keywords`**（その記事のソースのもの）：空でなく、どれも含まなければ外す。

### キーワードの照合
- 照合する文字列は、`title` と、`content` から HTML タグを取り除いた先頭 1,000 文字をつないだもの。
- 照合する文字列とキーワードの両方を、Unicode の NFKC 正規化（全角英数字を半角に、半角カナを全角に、など）と大文字・小文字の同一視（`casefold`）をしてから、部分一致で比べる。
  - 例：キーワード `claude` は `Claude`、`CLAUDE`、`Ｃｌａｕｄｅ` に一致する
  - 部分一致なので、`GPT` は `ChatGPT` にも一致する

### 記録
- 外した記事は `articles.status` を `skipped` にする。通した記事の `status` は変えない。
- この処理は DB をコミットしない（003 と同じ）。
- 外した件数を理由ごとに INFO ログに出す。外した記事は 1 件ずつ、理由と URL を DEBUG ログに出す。

## エラー時の挙動
| 状況 | 動作 |
|---|---|
| `exclude_keywords` の値が不正 | `ConfigError`（001） |
| 記事のソースが設定に無い | 003 で除外済みのため起きない。万一あれば、ソース別ルールは適用せず（時間窓と共通の除外キーワードだけで判定し）、WARNING ログを出す |
| DB の操作で例外が起きた | 例外をそのまま呼び出し側に渡す |

## 受け入れ基準
### 時間窓
- **AC-005-1**: Given 現在日時と `TIME_WINDOW_HOURS = 36`、公開日時が 35 時間前・ちょうど 36 時間前・37 時間前の記事 / When 絞り込む / Then 35 時間前とちょうど 36 時間前の記事は通り、37 時間前の記事は外れる
- **AC-005-2**: Given 公開日時が 5 日前の、`qiita_search` と `zenn_topic` のソースの記事 / When 絞り込む / Then 時間窓では外れない
- **AC-005-3**: Given 公開日時の無い記事 / When 絞り込む / Then 時間窓では外れない

### キーワード
- **AC-005-4**: Given 全ソース共通の除外キーワードを、タイトルまたは本文に含む記事 / When 絞り込む / Then 外れる
- **AC-005-5**: Given ソース A の `hide_keywords` を含む、ソース A の記事とソース B の記事 / When 絞り込む / Then ソース A の記事だけが外れる
- **AC-005-6**: Given `require_keywords` のあるソースの、キーワードを 1 つも含まない記事と 1 つ含む記事、`require_keywords` の無いソースの記事 / When 絞り込む / Then 1 つも含まない記事だけが外れる
- **AC-005-7**: Given キーワード `claude` と、タイトルが `CLAUDE`・`Ｃｌａｕｄｅ`（全角）の記事 / When 絞り込む / Then どちらも一致する
- **AC-005-8**: Given キーワード `div` と、本文に `<div>` タグだけを含む記事、キーワードが本文の 1,000 文字目より後ろにだけある記事 / When 絞り込む / Then どちらも一致しない

### 記録と出力
- **AC-005-9**: Given 外れる記事と通る記事 / When 絞り込む / Then 外れた記事の `status` は `skipped`、通った記事の `status` は `new` のまま。呼び出し側がロールバックすると、`status` は元に戻る（コミットしない）
- **AC-005-10**: Given 複数の理由で外れる記事を含む入力 / When 絞り込む / Then 通った記事が入力の順で返り、理由ごとの件数が INFO ログに出る。時間窓と除外キーワードの両方に当てはまる記事は、時間窓の理由で数える

### 設定（001 の変更）
- **AC-005-11**: Given トップレベルに `exclude_keywords` がある / 無い `sources.yaml` / When 読み込む / Then `LoadedSources.exclude_keywords` はそのリスト / 空のリストになる
- **AC-005-12**: Given `exclude_keywords` がリストでない、または空の文字列を含む `sources.yaml` / When 読み込む / Then `ConfigError` が送出される

## 実装方針（参考）
- モジュール：`src/aidigest/pipeline/prefilter.py`
- HTML タグの除去は正規表現（`<[^>]+>`）で行う。本文の抽出（trafilatura）は 010 で使うもので、ここでは使わない

## 決定事項
1. **照合する範囲**：タイトルと本文の先頭 1,000 文字とした。本文全体を見ると、本文中でたまたま触れただけの語（例：`Python`）で外れてしまうため。タイトルだけにすると、`require_keywords` で拾える記事が減る。
2. **部分一致**：単語の区切りは見ない。日本語には単語の区切りが無いため。英語の短い語（例：`AI`）は `MAIL` などにも一致するので、キーワードを選ぶときに注意が要る。
3. **全ソース共通の除外キーワードの初期値**：空にする。SPEC §3 の「除外」テーマ（.NET / Python の一般的な開発手法など）はキーワードで一律に外すと誤りが多いので、006 のスコアの減点で扱う。実際の配信を見て、明らかに要らない語が分かったら足す。
4. **置き場所**：`sources.yaml` のトップレベルとした。`topics.yaml` は 006 で採点用に作るもので、ここでは使わない。
