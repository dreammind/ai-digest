# specs/ — 機能単位の詳細仕様

`SPEC.md` を全体の正とし、各機能の詳細はこのディレクトリに置く（SPEC.md §11）。

## 運用ルール
- ファイル名は `NNN-<name>.md`（例: `003-url-normalize.md`）。番号は 3 桁の連番で、着手順に振る。
- 実装に着手する前に仕様を書き、承認を得る。
- 受け入れ基準には `AC-NNN-x` の ID を振る（例: `AC-003-2`）。1 つの基準に 1 つ以上のテストを対応させる。
- テスト名かコメントに受け入れ基準 ID を入れる（例: `def test_strips_utm_params() -> None:  # AC-003-1`）。
- 仕様にない挙動が必要になったら、実装を止めて、仕様の修正案を出す。
- 完了前に、仕様・テスト・実装が一致していることを確認する。
