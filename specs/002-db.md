# 002: SQLite のスキーマとマイグレーション

- 状態: 実装済み
- 関連: SPEC.md §7（データ構造）、001（設定）

## 目的
SPEC §7 のテーブルを SQLite に作り、番号付きのマイグレーションでスキーマを管理する。
後続の機能（003 以降）は、ここで開いた接続を使って読み書きする。

## 範囲
- 含む:
  - DB ファイルを開く（無ければ作る）処理と、接続の設定
  - マイグレーションの仕組み（`schema_version` による管理、未適用分の適用）
  - 初期スキーマ（SPEC §7 の 6 テーブル）
  - 設定項目 `DB_PATH` の追加（001 の `Settings` に足す）
- 含まない:
  - 各テーブルへの読み書き（記事の登録、既読判定、費用の集計など）：使う機能の仕様（003、004、007 など）で定める
  - 保持期間による削除（記事 90 日 / 1 年、`digests.html` 90 日）：Phase 1 には含めない（Phase 2 以降）
  - `--dry-run` のときに DB をどう扱うか：013 で定める

## 入出力
- 入力: `DB_PATH`（`.env` / 環境変数。既定値は `data/aidigest.db`）
- 出力: マイグレーション適用済みの `sqlite3.Connection`
- マイグレーション: `src/aidigest/migrations/NNNN_<name>.sql`（4 桁の連番、1 始まり）

## 振る舞い
1. `DB_PATH` の親ディレクトリが無ければ作る。
2. 接続を開き、外部キー制約を有効にする（`PRAGMA foreign_keys = ON`）。行は列名でも参照できるようにする（`sqlite3.Row`）。
3. `schema_version` テーブルが無ければ作る。列は `version`（INTEGER PRIMARY KEY）と `applied_at`（適用日時）。
4. 現在のバージョン（`schema_version` の最大値。無ければ 0）より大きい番号のマイグレーションを、番号の順に適用する。
5. マイグレーションは 1 つずつトランザクションで適用し、成功したら同じトランザクションで `schema_version` に記録する。
6. 日時はすべて UTC の ISO 8601 文字列（例：`2026-10-15T21:30:00+00:00`）で保存する。

### 初期スキーマ（0001）
SPEC §7 の列をそのまま作る。SPEC に書かれていない制約と索引は、次のとおり追加する。

| テーブル | 列（SPEC §7） | 追加する制約・索引 |
|---|---|---|
| `runs` | id, started_at, finished_at, fetched_count, selected_count, sent_count, error | `id` は自動採番。`started_at` は NOT NULL |
| `articles` | id, url, source_id, category, title, published_at, fetched_at, content_hash, local_score, llm_score, final_score, matched_topics, summary_json, score_model, summary_model, status | `url` は UNIQUE。`url`、`source_id`、`title`、`fetched_at`、`content_hash`、`status` は NOT NULL。`status` は `new` / `scored` / `selected` / `summarized` / `sent` / `skipped` のみ（既定値 `new`）。`fetched_at` に索引 |
| `digests` | id, run_id, created_at, status, article_count, html, article_ids | `run_id` は `runs.id` への外部キー。`status` は `sent` / `dry_run` / `empty` / `failed` のみ。`html` は NULL 可（保持期間の後に NULL にするため） |
| `llm_calls` | id, run_id, purpose, model, input_tokens, output_tokens, cost_usd, created_at | `run_id` は `runs.id` への外部キー。`purpose` は `rerank` / `summarize` のみ。`created_at` に索引（日次・月次の費用集計のため） |
| `source_health` | run_id, source_id, status, error, item_count | `run_id` は `runs.id` への外部キー。主キーは (`run_id`, `source_id`)。`status` は `ok` / `error` のみ |
| `schema_version` | （SPEC は「マイグレーション管理用」とだけ記載） | 上記の振る舞い 3 のとおり |

- JSON を入れる列（`matched_topics`、`summary_json`、`article_ids`）は TEXT とする。
- 費用（`cost_usd`）は REAL、スコアは REAL、件数とトークン数は INTEGER とする。

## エラー時の挙動
| 状況 | 動作 |
|---|---|
| マイグレーションの途中で失敗した | そのマイグレーションをロールバックし、`DbError` を送出する。それまでに適用したバージョンとデータは残る |
| DB のバージョンが、コードが知っている最新より新しい | 何も変更せず `DbError` を送出する（古いコードで新しい DB を壊さないため） |
| マイグレーションの番号に欠番や重複がある | 何も適用せず `DbError` を送出する |
| DB ファイルを開けない（権限など） | `DbError` を送出する |

## 受け入れ基準
- **AC-002-1**: Given DB ファイルが存在しない / When DB を開く / Then 親ディレクトリとファイルが作られ、6 テーブルがそろい、`schema_version` が最新の番号になる。`applied_at` は UTC の ISO 8601 文字列で記録される
- **AC-002-2**: Given 最新まで適用済みでデータが入っている DB / When もう一度開く / Then マイグレーションは適用されず、データはそのまま残る
- **AC-002-3**: Given バージョン 1 の DB と、マイグレーション 1・2 / When DB を開く / Then 2 だけが適用され、バージョンが 2 になる
- **AC-002-4**: Given 途中の文で失敗するマイグレーション 2 / When DB を開く / Then `DbError` が送出され、バージョンは 1 のまま、マイグレーション 2 で作りかけたものは残らない
- **AC-002-5**: Given コードの最新より新しいバージョンの DB / When DB を開く / Then `DbError` が送出され、DB は変更されない
- **AC-002-6**: Given 番号に欠番または重複があるマイグレーションの一覧 / When DB を開く / Then `DbError` が送出され、何も適用されない
- **AC-002-7**: Given 初期スキーマを適用した DB / When 各テーブルの列を調べる / Then SPEC §7 に書かれた列がすべてある
- **AC-002-8**: Given `articles` に登録済みの URL / When 同じ URL の記事を登録する / Then 一意制約の違反になる
- **AC-002-9**: Given 初期スキーマを適用した DB / When `articles.status`、`digests.status`、`llm_calls.purpose`、`source_health.status` に許可されていない値を入れる / Then 制約違反になる
- **AC-002-10**: Given 初期スキーマを適用した DB / When 存在しない `run_id` で `digests`、`llm_calls`、`source_health` に登録する / Then 外部キー制約の違反になる
- **AC-002-11**: Given `DB_PATH` を設定していない / When `Settings` を作る / Then `db_path` は `data/aidigest.db` になる。`.env.example` に `DB_PATH` が載っている（AC-001-13 のテストで確認する）
- **AC-002-12**: Given `DB_PATH` が開けない場所を指している（例：ディレクトリ） / When DB を開く / Then `DbError` が送出される

## 実装方針（参考）
- 標準の `sqlite3` だけを使い、ORM は入れない
- マイグレーションは `.sql` ファイルとし、`importlib.resources` で読む。テストでは、マイグレーションの一覧を引数で差し替えられるようにする
- テストは一時ディレクトリの DB ファイルを使う
- `data/` を `.gitignore` と CLAUDE.md のディレクトリ構成に追加する
